# 高性能磁盘调度与存储系统设计与实现

本次比赛考察的是如何安排磁盘的存储，调度磁头的读取，以最快的时间响应请求。

1. 在磁盘选择方面，我实现了多个思路

   - 每当有物品请求加入时，选择空闲最多的磁盘

   - 对于热门物品，均匀分布于各个磁盘；其余物品空闲最多的磁盘放

2. 在磁盘空间分配上，我实现了多个思路

   - 热物品存放于热区，热区根据请求数量动态调整；冷门物品从磁盘最后倒向存储
   - 将磁盘按照 tag 分区，热物品与冷物品的分区交替
   - 将磁盘按照 tag 分区，热物品区域在中间，冷物品区域在最后

3. 在磁头读取方面，我实现了多个思路

   - SCAN 电梯算法，根据待读取请求集合，生成读取路径

   - 动态规划算法，根据 $\max_{\text{target}}f(\text{target}), V(pos+1, c_{remaining} - 1, 0)$ 和 $s_i(t) + V(pos + 1,  c_{remaining} - token[l_{prev}], l_{prev} + 1)$
     选择 jump，pass 以及 read 中收益最高者，作为决策路径。其中 $f$ 为衡量跳跃后的收益的函数，具体有几种实现：

     (0) 考虑未来动态规划的收益 

     (1) 不管收益，直接跳到热区开头

     (2) 在磁盘分块情况下，考虑收益（或收益/令牌消耗数）最大的分块

4. 在请求调度方面，我实现如下

   - 请求根据物品大小分为高价值请求，中价值请求，低价值请求
   - 根据每个时间片处理的速度，以及各层次请求的数量，动态调整每个时间片处理的请求数
   - 根据请求选择合适的副本进行读取
   - 如果队列中的请求过长时间没被处理，它的优先级会下降
